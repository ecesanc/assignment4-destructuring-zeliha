Assignment 4:
Destructuring Field Guide

Write a careful, documented guide to destructuring in JavaScript and TypeScript: const [x, y] = f(), let { a, b } = t and everything around them, ending with how React components take apart props and children. This is a documentation assignment. The code is small. What we grade is that you understood it and can explain it. It is worth 100 points, and four optional parts are bonuses of 5 points or more each.

Format
Individual assignment.

JavaScript and TypeScript (strict). The guide itself is Markdown. LaTeX is a bonus.
Source
The starter project in starter/ and the destructuring parts of the slides and of the Task Manager sample.
Deadline
Set in Moodle (the course platform) when the assignment is posted.
Points
100 for the assignment and 5 or more for each of the four bonuses: 120 or more in total.

Abbreviations and Key Terms

AI
Artificial Intelligence, as in AI coding assistants.
children
A special prop. Whatever you write between the opening and closing tags of a component, <Card>this</Card>, arrives in the component as props.children.
default value
A value used when the item is missing (undefined): const { size = 10 } = options.
destructuring
Taking values out of an array or an object into separate variables with one pattern on the left: const [x, y] = f() or let { a, b } = t.
JSX
The HTML-like syntax inside JavaScript and TypeScript files that React turns into function calls.
LaTeX
A typesetting system for documents with a lot of structure and code. The source is plain text and the output is a PDF.
Moodle
The course platform: you download materials and upload assignments there.
pattern
The left side of a destructuring: the shape you describe, such as [first, ...rest] or { a, b }.
props
The single object a React component receives. Its fields are the attributes you write in JSX.
rest
The ...name in a pattern that collects what is left over into a new array or object.
spread
The ...value in an expression that expands an array or object into separate items or fields. It looks like rest but does the opposite job.
TS
TypeScript, JavaScript with static types.
tuple
A TypeScript array type with a fixed length and a type for each position, such as [number, string].

The twelve forms

Each form gets code in JavaScript, the same code in TypeScript, and an entry in the field guide.

Hints. Try each form with a value that is missing, with undefined and with null. Ask yourself what the pattern would look like as plain assignments, one line per variable, and write that down: it is the best way to explain what the pattern does. Rest in a pattern (...others) and spread in an expression ([...list]) use the same three dots for opposite jobs; say so in your guide.

Props and children

This is the main part of the assignment. A React component receives one object, its props. The object has the attributes you wrote in JSX, and it also has the content you put between the tags, under the name children. Destructuring is how almost every component takes this object apart, so this is where the forms from this assignment meet your real code. Your job is to separate the two ideas, props and children, and to show that you understand the difference, not only the syntax.

Show every topic in code that runs (render it with renderToStaticMarkup, as the starter does, and paste the real output into your guide) and explain it in your own words.

TopicWhat you show
P1Props is one object. function Card(props) and function Card({ title, children }) do the same thing. Show both, and say what the second one is in terms of forms 5 and 11.
P2children is only a prop. <Card>text</Card> and <Card children="text" /> give the same result. Show it with the rendered output.
P3What children can be. A string, a number, one element, several elements, undefined, null, false, a function. Render each one and write what appears, and what does not.
P4Separating children from the other props. ({ title, children, ...rest }), and rest spread onto a DOM element, <section {...rest}>. Show how the order of the spread and an explicit prop decides which one wins.
P5Props or children? The same component built twice: once with a header and a footer prop, once with children only. Say when you would choose each one and why.
P6Defaults. A default for a prop with form 7. Show that undefined triggers the default and null does not, and what that does on the screen.
P7Types. children?: ReactNode, PropsWithChildren and ComponentProps<'button'>. Show what each one allows and what the compiler rejects.

How an entry looks

Every one of the twelve entries has the same five parts. This is one entry as an example; do not copy it, write your own with your own data.

README.md
### Form 6: rename while you take it, `const { title: heading } = task`

**Syntax:** `const { title: heading } = task`

**Example** (from `js/objects.mjs`, my own data):

```js
const book = { title: 'Dune', year: 1965 }
const { title: name } = book
console.log(name)
```

**Output:** `Dune`

**Use it when:** the property name clashes with a variable you already have,
or the name is not clear in this place.

**Watch out:** the old name is NOT a variable after this. `title` does not exist here,
only `name` does. (Reading it as "title becomes name" is what makes it easy to remember:
the source is on the left of the colon and the new name is on the right.)

Troubleshooting

What you seeWhy, and what to do
TypeError: Cannot destructure property 'a' of 'undefined'The value on the right is undefined or null. Give the parameter a default (= {}) or check the value first.
SyntaxError on { a } = objA line that starts with { is read as a block. Write ({ a } = obj) with parentheses, or use const.
A variable is undefined although the field existsYou may have renamed it: in { a: b } the variable is b, and a does not exist.
ReferenceError: React is not definedThe JSX setting is missing. Keep jsx: "react-jsx" in tsconfig.json and run the file with npx tsx.
Object is possibly 'undefined' after const [first] = itemsnoUncheckedIndexedAccess is on, so an array item may be missing. Check it, or give it a default.
Property 'children' does not exist on typeYour props type does not list children. Add children?: ReactNode or use PropsWithChildren.
